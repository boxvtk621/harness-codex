# Node settings v2 (Codex)

`GET /v1/nodes/{nodeId}/settings` returns `schemaId: "harness-node-settings-v2"`, `mcpSchema: "harness-mcp-document-v2"`, `draftRevision`, `appliedRevision`, `draft`, optional `applied`, `capabilities`, and the latest apply operation. Both settings objects contain `inference` and `mcpDocument`. `mcpDocument` has `schemaId: "harness-mcp-document-v2"` and a `servers` array. A new node has an empty `servers` array. The snapshot never contains secret values.

`PUT /v1/nodes/{nodeId}/settings` accepts `{ "expectedRevision": 0, "draft": { "inference": { "modelId": null, "speedMode": "off", "reasoningEffort": null }, "mcpDocument": { "schemaId": "harness-mcp-document-v2", "servers": [] } } }`. It replaces the entire draft, subject to compare and swap on `draftRevision`. A stale revision returns 409 with the current snapshot. A successful PUT increments `draftRevision`; the existing `POST .../settings/apply` is the sole activation path. Apply still accepts `commandId`, `expectedRevision`, and `targetRevision` and returns the durable operation receipt.

HTTP MCP entries have `id`, `name`, `enabled`, `transport: "streamable_http"`, an HTTPS `url`, `timeoutMs` (100–30000), and `auth`. Input `auth` has `kind: "none" | "bearer"`, `secretAction: "keep" | "replace" | "remove"`, and `secret` only for `replace`. Output `auth` has `kind` and `bearerTokenConfigured`. The bearer slot is stable under the server `id`. SSE is unsupported.

Stdio entries have `id`, `name`, `enabled`, `transport: "stdio"`, `command`, `args`, `timeoutMs`, and `secretSlots`. Each input slot is `{ "slot": "API_KEY", "action": "replace", "secret": "..." }`, with `secret` only for `replace`. The slot name is the child process environment variable. `keep` uses the slot already saved under the same server `id`; `remove` deletes it. An existing slot on a retained server requires an explicit action. Output slots are `{ "slot": "API_KEY", "configured": true }`. Plain environment values are not accepted on the public wire. The adapter passes saved slot values only to the native MCP process configuration, and never exposes them in the snapshot.

`POST /v1/nodes/{nodeId}/settings/mcp-validate` accepts `{ "mcpDocument": { ... } }`. It checks an unsaved document locally, without writing, restarting, or connecting to MCP servers. Its response is `{ "schemaId": "harness-mcp-validation-v2", "valid": true | false, "errors": [{ "path": "/mcpDocument/servers/0/url", "code": "invalid" }] }`. Invalid PUT input returns 400 with `code: "invalid"` and an `errors` array with JSON Pointer paths; unknown JSON fields use `code: "unknown_field"`. `POST .../settings/mcp-checks` continues to check a **saved** server and requires `{ "expectedRevision": 1, "mcpServerId": "..." }`.

`GET .../settings/model-catalog` lists actual native reasoning levels, `isDefault` per model, and public `speedModes`: `off` always, `on` only if the native model offers `priority`. `compatibility: "unknown"` indicates that the native catalog does not provide pairwise reasoning/speed compatibility. The adapter validates each selected value against the selected model and verifies the complete selection during apply. `modelId: null` uses the native catalog's default model and sends JSON `null` for model at thread start, resume, and turn start. `reasoningEffort: null` resolves the selected model's current `defaultReasoningEffort` from the native catalog and sends that explicit value; native `model_reasoning_effort: null` is rejected by pinned Codex 0.155.1. `speedMode: null` or `off` sends native `serviceTier: "default"`; `on` sends `"priority"`.

On opening persisted `harness-node-settings-v1` state, Codex migrates it to v2 in place. Native speed tier `priority` becomes public mode `on`, and `default` becomes `off`, in both draft and applied settings. The same conversion repairs v2 files written by an earlier migration before speed translation. Existing HTTP server fields, bearer slot values and versions, draft/applied revisions, and apply receipts are retained. The state file name remains `node-settings-v1.json` for compatibility. The old flat `draft.mcpServers` PUT shape remains accepted for existing clients, although new clients should use `mcpDocument`.
